# الدلتا — Delta

الدلتا لتجارة وتوزيع الخردوات والمنتجات الاستهلاكية — المخزن في مركز الزرقا بمحافظة دمياط.
واجهة متجر عربية (RTL) مبنية بـ React + Vite + JavaScript وCSS عادي — بدون TypeScript، بدون Tailwind، وبدون Backend أو قاعدة بيانات في هذه المرحلة.

> كل المعرّفات الداخلية صارت باسم الدلتا: الحزمة `delta-store`، مفاتيح التخزين المحلي `delta-store:cart` و`delta-store:orders` و`delta-store:order-status-overrides`، وبادئة أرقام الطلبات وأرقام الأصناف `DL-`. أي سلة أو طلب كان محفوظًا في المتصفح تحت المفاتيح القديمة `united-store:*` ما بقي يُقرأ — تختفي من الواجهة وتبقى في المتصفح حتى يمسحه المستخدم.
> ثلاثة مفاتيح جديدة تضيفها هذه المرحلة: `delta-store:delivery-rules` (رسوم التوصيل وحدّيه)، `delta-store:stock-counts` (سجل العدّ في اللوحة)، و`delta-store:catalog-overrides` (تعديلات المنتجات بما فيها مكان الرف). ورابع من جانب العميل: `delta-store:recently-viewed` (آخر ٨ أصناف بصفحتها في الرئيسية، بلا حساب وبلا أي بيانات شخصية).

## التشغيل

```bash
npm install
npm run dev      # خادم التطوير
npm run build    # بناء الإنتاج
npm run lint     # فحص الكود (oxlint)
npm test         # اختبارات Vitest + Testing Library (238 اختبارًا)
npm run preview  # معاينة نسخة البناء
npm run dev -- --host   # فتح خادم التطوير على الشبكة المحلية ليشتغل على الموبايل (http://<ip>:5173)
```

## المسارات

| المسار | الوصف |
| --- | --- |
| `/` | الرئيسية: «شوفت من قبل» (يظهر لما يبقى في سجل تصفّح على الجهاز)، الأقسام، الأكثر طلبًا، شرح الجملة. قسم «عروض تجريبية» اترفعت — النسخة التجريبية ما بتعرضش خفض أسعار في الواجهة الرئيسية. تخفيض `offerPrice` نفسه لسه شغال في التسعير ولوحة الجملة، ورابط «العروض» في الفوتر و«تصفية سريعة › عروض» لسه في مكانهم |
| `/products` | كل المنتجات: بحث عربي مُطبَّع + فلاتر القسم والتصفية السريعة في عمود جانبي ثابت (مع عدد الأصناف لكل فلتر) وترتيب بالسعر والاسم. **فوق الشبكة شريط دائري للتنقّل (`SectionRail`)** — الأقسام الرئيسية ستة عشر دائرة، واختيار قسم يفتح شريط ما تحته جنب المنتجات، والورقة اللي مفيش تحتها أقسام تعرض إخوتها في أبيها، فوقها ممرّ (`catalog-crumbs`) يطلع خطوة بخطوة لـ«كل الأقسام». **الدائرة تفلتر على القسم نفسه بس** — أصناف الأبناء ما تطلعش، والقسم الأب اللي مفيش عليه أصناف مباشرة يعرض إرشادًا لأبنائه بدل شبكة فاضية. واختيار قسم من الشريط **ما يسقطش** البحث ولا حدّ السعر ولا الترتيب (`catalog.hrefFor`). وفي لوحة الفلاتر (العمود الجانبي) الشريط يعرض الأقسام الرئيسية فقط، وما تحتها — بمستوييه إن وُجد — ينفتح بضغطة على السهم، والقسم المختار يفتح أبنائه تلقائيًا. الصنف اللي لسه بلا سعر يكتب «السعر يُحدَّد» بدل صفر والفلترة بالسعر تستبعده. مكان الرف لا يظهر هنا أبدًا. وعلى الهاتف تحت 1000px الفلاتر بتختفي ورا زرار «الفلاتر» (شريط لاصق علوي فيه الزرار بعدد الفلاتر الشغّالة + العدّ + الترتيب)، واللوحة تنفتح كطبقة فوق القائمة وتُقفل herself بعد اختيار قسم أو وسم أو «إزالة الفلاتر» |
| `/products/:slug` | صفحة الصنف: السعر حسب الكمية، جدول الأسعار، أصناف مشابهة (حتى ٨: ورقة القسم، فجوّارها تحت أبيهم، فلقسم الرئيسي كله). أزرار كميات جاهزة (عبوة / حد الجملة / ضعف الحد) وملاحظة «الكمية تعادل N قطعة». زرارّا «كلّمنا عن…» و«اسأل على واتساب» يظهرون **لما** يكون `contact.phone` أو `contact.whatsapp` معتمدًا فقط — ومعهم `null` الآن لا يظهر أي منهما |
| `/categories` | الأقسام الرئيسية الستة عشر كبطاقات **صورها دائرية** — صورة القسم التي ملّها التاجر وإلا صورة صنف ممثل من جوه وإلا أيقونة القسم — وعدد الأصناف ومدى الأسعار ورابط التصفح وروابط أقسامها الفرعية. وفوق البطاقات شريط `SectionRail` بعناوين «اختر قسمك» يقود مباشرة لتصفّح القسم (بلا دائرة «كل الأقسام» هنا، فالصفحة نفسها عرض للقسمات كلها) |
| `/wholesale` | طريقة الحساب وجدول حدود الجملة لكل صنف، مع محتوى العبوة والمجموع بالقطعة عند الحد الأدنى — ستة أعمدة تظهر كاملة بلا تمرير أفقي |
| `/cart` | السلة الكاملة مع تعديل الكميات والحذف والإفراغ، مع شريطي «ناقصك X للتوصيل المجاني» و«طلب الجملة يبدأ من Y» حسب إعدادات اللوحة |
| `/checkout` | فورم يعمل: تحقق من الحقول، اختيار المحافظة من قائمة المحافظات المصرية، العنوان التفصيلي، **بند التوصيل المحسوب من المحافظة** (يتغير اختيار المحافظة فيتحديث البند والمطلوب)، تسجيل الطلب محليًا، ثم تحويل إلى صفحة التأكيد |
| `/order/:number` | تأكيد الطلب برقمه وأصنافه وإجماليه وبند توصيله (تُقرأ من متصفحك) + فاتورة وإعادة طلب |
| `/invoice/:number` | فاتورة الطلب منسّقة للطباعة أو الحفظ PDF من المتصفح، بإجمالي أصناف وبند توصيل (أو «توصيل مجاني / بلا مقابل») والمبلغ المطلوب — سبعة أعمدة تظهر كاملة بلا تمرير أفقي، وتتحول بطاقات على الهاتف |
| `/pick/:number` | ورقة تجهيز الطلب للطباعة: الأصناف والكميات ومحتوى العبوة بدون أسعار، مع مربّع تحديد لكل صنف وخانة «المكان» (مطبوعة من اللوحة إن كانت مكتوبة، ومخطّطة لغير ذلك) — سبعة أعمدة بلا تمرير أفقي، والمربّع يشتغل في حالة البطاقة كمان |
| `/track` | تتبع الطلب **برقم التليفون**: كل الطلبات المسجّلة على نفس الرقم في قائمة، واختيار رقم يعرض مراحله |
| `/dashboard` | لوحة التحكم للتاجر بتبويبات في شريط جانبي: نظرة عامة + تنبيهات، الطلبات، المنتجات (إضافة/تعديل/إخفاء + عدّ الجرد + تصدير جرد CSV)، تسعير الجملة، **التوصيل وحد الجملة**، العملاء والتواصل. تُحمَّل كحزمة `Dashboard-*.js` مستقلة أول ما تُطلب (`lazy` + `Suspense`)، فما تنزلش على موبايل العميل اللي ما بيفتحهاش. **وفي نسخة الإنتاج وحدها تفتح وراء رمز** (`DashboardGate`) — انظر بند النشر |
| `/about`, `/contact` | عن الشركة وقنوات التواصل — كل قناة معتمدة بتبقى رابطًا شغالًا (`tel:` أو `wa.me` أو `mailto:`)، واللي لسه `null` يفضل سطرًا أمينيًا «لم تُعتمد بعد» |
| أي مسار آخر | صفحة 404 |

## الطلبات (محليًا بالكامل)

- `/checkout` يتحقق من الاسم (٣ أحرف+) ورقم هاتف مصري بصيغة `01[0125]XXXXXXXX`، و**المحافظة إلزامية من قائمة المحافظات المصرية الـ٢٧** (`src/data/governorates.js`)، مع خانة **العنوان التفصيلي** (اختيارية، بحد ١٢٠ حرفًا) ليحدد العميل المكان بالظبط. يقبل الرقم بمسافات أو شرطات أو أرقام عربية، ويركّز على أول حقل خاطئ ويُظهر إشعارًا واضحًا قبل التسجيل. التحقق كله في `src/utils/checkout.js`.
- عند النجاح يُولَّد رقم تسلسلي `DL-26xx` من `nextOrderNumber` في `src/data/orders.js`، وتُحفظ نسخة من أصناف السلة بأسعارها النهائية (لقطة، لا تُشتق لاحقًا)، ثم تُفرَّغ السلة ويُفتح `/order/:number`.
- المحافظة والعنوان التفصيلي يظهرون في صفحة التأكيد والفاتورة ولوحة التحكم وملف CSV المُصدَّر، ويدخلان في بحث اللوحة.
- مع كل طلب جديد يُخزَّن بند توصيله كلقطة ثابتة `delivery:{label, amount}` لحظة التسجيل؛ تعديل السياسة لاحقًا من تبويب «التوصيل» لا يغيّر فاتورة صدرت. الطلبات المسجَّلة قبل هذه المرحلة تُقرأ بدون بند وتظهر بمقابل صفر.
- كل ما يعرض «المبلغ المطلوب» (التأكيد، الفاتورة، التتبع، اللوحة، CSV) يمرّ عبر `payableOf(order)` في `src/utils/delivery.js`، بينما يبقى `orderTotals` لإيراد الأصناف وحده — فلا يدخل التوصيل في مؤشرات المبيعات.
- الطلبات المخزّنة في `localStorage` بمفتاح `delta-store:orders`؛ وحالات الطلبات التجريبية في `src/data/orders.js` لا تُعدَّل في الملف، بل تُحفظ كتغطيات حالة في `delta-store:order-status-overrides` حتى لا تُفقد البيانات الأصلية.
- `OrderTracking` و`Dashboard` يقرآن من نفس المخزن (`src/context/OrderContext.jsx`)، فتغيير الحالة من اللوحة يظهر فورًا في صفحة التتبع وبعد التحديث.
- **لا يوجد خادم**: لا يُرسل أي طلب لأي جهة، ولا يصل إلى الشركة، فلا تُدخل بيانات عملاء حقيقية. من تبويب الطلبات يوجد زر «مسح الطلبات المحلية» (بتأكيد من خطوتين) لإزالة كل ما خُزّن في المتصفح.
- الطلبات القديمة المحفوظة في متصفحك قبل إضافة خانة العنوان تُقرأ بـ `address: ''` بدون أي ترحيل.

## لوحة التحكم (تبويبات)

`/dashboard` لم تعد «لوحة طلبات»: صفحة واحدة بشريط جانبي فيه ستة أقسام (`role=tablist` عمودي) والاختيار يُقرأ من الرابط `?tab=overview|orders|products|pricing|delivery|customers`، فيمكن مشاركة التبويب أو الرجوع إليه بالزر الخلفي، وكل تبويب يحتفظ بحالته داخله. الشريط لاصق (sticky) بجانب المحتوى ويعرض عدد العناصر اللي تحتاج إجراء على كل قسم (تنبيهات، طلبات بانتظار التأكيد، نافد، بلا جملة، عدّ بانتظار الاعتماد، عدد العملاء)، وبيتحول لشريط أفقي قابل للتمرير تحت 1000px. التنقل بالكيبورد: الأسهم يتحرك بين الأقسام، وHome/End لأول وآخر قسم.

- **نظرة عامة**: مؤشرات المبيعات (الطلبات، الإجمالي، الوحدات، المتوسط، آخر ٧ أيام) من `ordersSummary`، أشرطة توزيع الطلبات على المراحل، أكثر المحافظات طلبًا، حالة الكتالوج من `catalogHealth` (نافد/واطي/بلا جملة/مضاف/مخفي)، وعدد الأصناف عليها عدّ مسجَّل، وتنبيهات كل واحد منها زر يفتح التبويب المعني — منها «عدّ مسجَّل بانتظار الاعتماد» الذي يسمّي الصنف والعدد والفارق.
- **الطلبات**: كما هي — بحث وتصفية بالحالة والمحافظة، تغيير الحالة بمسارها المشروع، تصدير CSV للصفحة المعروضة، إعادة طلب، ورابط «تجهيز» يفتح ورقة الطباعة بدون أسعار، ومسح الطلبات المحلية بتأكيد من خطوتين. و«الحالة» تبقى قائمة `select` بنفس الخيارات والمسار المشروع، وتغييرها يومض الصف. جدول الطلبات بأعمدته الثمانية (رقم الطلب، العميل، النوع، التاريخ، الأصناف/الوحدات، المبلغ المطلوب، الحالة، إجراء) يظهر كاملًا على أي عرض **بلا تمرير أفقي** — التفاصيل في فقرة «كل الجداول بلا تمرير أفقي» تحت.
- **المنتجات**: جدول بكل صنف (صورة مصغّرة، القسم، **المكان**، الوحدة، الأسعار، المخزون، **العدّ**) + «صنف جديد» و«تعديل» بنفس نموذج إضافة الصنف (`ProductEditor`)، و«معاينة» تفتح صفحة الصنف كما يراها العميل، و«إخفاء» (تأكيد من خطوتين) يُخرج الصنف من المتجر والسلة والتتبع، و«استرجاع البيانات الأصلية» يمسح كل تعديلات اللوحة، و«تصدير الجرد (n)» ينزّل ملف CSV بالأصناف المعروضة بعد الفلاتر. البحث يشمل المكان ورقم الرف، وفيه شيبس «فروق جرد (n)» لعرض ما يختلف عدّه عن المكتوب فقط. أعمدة الجدول العشرة تظهر كاملة **بلا تمرير أفقي** على أي عرض.
- **تسعير الجملة**: تحرير الأسعار أربعة في الصف (قطاعي/عرض/جملة/حد الجملة) مع شارة فرق السعر لكل صنف، ومؤشرات (جاهز للجملة، بلا جملة، عليه عرض، متوسط الخصم)، وفلاتر بحث وقسم و«بلا سعر جملة». الجدول بسبعة أعمدة يظهر كاملًا **بلا تمرير أفقي**، وخانات السعر تتقلع مع عرض العمود بدل مقاس ثابت.
- **التوصيل وحد الجملة**: أربعة أرقام قابلة للتعديل (توصيل داخل دمياط والزرقا، توصيل لباقي المحافظات، حد الإعفاء، أقل قيمة لطلب جملة) مع حفظ واسترجاع للقيم الافتراضية، ومعاينة فورية لثلاثة طلبات مثالية تبيّن المقابل والمبلغ المطلوب وموقف كل طلب من حد الجملة. الحقول نصية بـ `inputMode=decimal` فتقبل الأرقام العربية، وترفض الفراغ والسالب والنص برسالة خطأ واضحة بدل أن تحفظ صفرًا. التفاصيل في فقرة «التوصيل وحد الجملة» تحت.
- **العملاء والتواصل**: تجميع الطلبات لكل عميل (اسم + إجمالي + وحدات + آخر طلب)، بحث بالاسم أو الهاتف أو المحافظة، ترتيب (الأعلى إنفاقًا/الأكثر طلبًا/الأحدث)، فلتر «المسجَّل في هذا المتصفح فقط»، وتوسّع يعرض طلبات العميل بروابط فواتيرها وتتبعها، مع بطاقة «قنوات التواصل» تعدّد الحقول التي لم تعتمدها الشركة بعد. جدول العملاء بسبعته يظهر كاملًا **بلا تمرير أفقي**.

### كل الجداول بلا تمرير أفقي

الجداول اللي تحتاج كل الأعمدة ظاهرة في وقت واحد — أربعة في اللوحة (الطلبات، المنتجات، التسعير، العملاء) وواحد في `/wholesale` (حدود الجملة) واثنان للطباعة (`/invoice/:number` بسبعة أعمدة و`/pick/:number` بسبعة) — بتشارك نظام `.dash-fit-table` في `src/styles/pages.css`، مع جدول معاينة التوصيل على التخطيط التلقائي اللي بيضغط نفسه. الفكرة إن ما نخفي ولا ندمج عمود، والجدول هو اللي يتكيّف:

- الحاوية `.table-scroll--{orders,products,pricing,customers,wholesale,pick}` و`.invoice-table-scroll` بتبقى container بـ `container-name: dash-table`، فالقياس على **عرض الجدول نفسه** لا على عرض الشاشة، لأن شريط التبويبات الجانبي ياخد عمودًا ثابتًا 218px في `.dash-shell` (زائد الفراغ منه) وأي `@media` على الشاشة بيغلط.
- `table-layout: fixed` + `<colgroup>` بنِسَب مئوية لكل عمود، مع `overflow-wrap: break-word` افتراضيًا عشان الأرقام زي `1,530` ما تتفككش، و`anywhere` بس على الخانات الطويلة حرفيًا (اسم العميل، الهاتف).
- ثلاث حالات عرض: واسع = الأزرار بتسمياتها؛ متوسط (تحت 1160 للمنتجات و1040 للطلبات والعملاء و820 للتسعير) = الأزرار أيقونات فقط، والتسمية الحقيقية بتفضل موجودة في `aria-label` و`title`؛ ضيّق (تحت 640) = كل صف بطاقة، الـ `thead` بيختفي وكل خانة بتاخد عنوانها من `data-label` عبر `::before`. وجداول الجملة والفاتورة وورقة التجهيز مفيهاش أزرار، فحالتين بس: أعمدة فوق 640 وبطاقات تحتها.
- التسميات الطويلة بتتجزأ بذكاء: `اعتماد<span className="btn__text"> في المخزون</span>` بتفضل «اعتماد» لوحدها على العرض المتوسط، و`مسح<span className="btn__text"> العدّ</span>` كذلك.
- `min-inline-size` إلغاؤه هو اللي كان بيفرض التمرير — اتشال من `.dashboard-table` والمنتجات والعملاء والتسعير والجملة (640px) والفاتورة (640px) وورقة التجهيز (560px). وفي صفحة الجملة كمان `white-space: nowrap` على الخلايا اتبدّل بـ `normal` لأنه كان بيمنع العمود إنه يتف.
- أسطر مجاميع الفاتورة (`tfoot`) ليها معالجة خاصة داخل البطاقة: `tfoot` بيتحول `block`، وقيم «الوحدات» و«الإجمالي» بتاخد عناوينها، وسطرا التوصيل و«المبلغ المطلوب» بيظهروا عنوان وقيمة. سطر الإجمالي الأول كانت خانة `—` حشو تحت عمودين، بقت `colSpan={4}` + `colSpan={2}` بنفس عدد الأعمدة وبلا حشو.
- الطباعة محروسة: `src/styles/print.css` بيحط `container-type: normal` على `.invoice-table-scroll` و`.table-scroll--pick` جوه `@media print`، فالورق ما يعرفش حالة البطاقة خالص والجدول بيتطبع بأعمده كاملة، مع بقاء `table-layout: fixed` والنِسَب المئوية اللي بتتوزّع على عرض A4.
- مقياس التحقق: وسّعنا وضيّقنا عرض الحاوية رقميًا من 1400 نزولًا إلى 500 (والجملة والفاتورة والتجهيز حتى 380) وقِسنا `scrollWidth > clientWidth` للحاوية ولكل خانة — صفر تجاوز في الجداول السبعة، وبصفّ فيه تعديل غير محفوظ ورسالة خطأ تحت خانة تسعير، وبمربع «تم» اتظغط فعليًا في بطاقة ورقة التجهيز (العدّاد تحرك لـ«جهّزت 1 من 1»).

### الكتالوج الحي (طبقة تعديلات بلا تعديل الملفات)

- `src/utils/catalogStore.js` يخزّن التعديلات في `localStorage` بمفتاح `delta-store:catalog-overrides` على ثلاثة أقسام: `patches` (حقول معدَّلة لكل صنف)، `created` (أصناف أضفها التاجر)، `removed` (أصناف مخفية). ملف `src/data/products.js` **لا يتغيّر**، والكتالوج المعروض = البذرة + التعديلات والمضاف − المخفي.
- كل الصفحات تقرأ من نفس المصدر عبر `useCatalog()` (`useSyncExternalStore`)، فأي تعديل في اللوحة يظهر فورًا في الرئيسية والمنتجات والصنف والسلة والفاتورة والتتبع — وبالعكس، الطلب المسجَّل يلتقط لقطة الأسعار وقت الشراء.
- الحقول القابلة للتعديل محدودة بقائمة بيضاء (`EDITABLE_FIELDS`، تشمل الآن `location` و`stock`)، و`validateProductForm` ترفض السالب في السعر والمخزون و`packSize`، وتطلب الاسم والقسم والسعر القطاعي، وتحدّ مكان الرف في ٢٤ حرفًا، و`validatePriceDraft` تفرض: قطاعي أكبر من صفر وبحد منطقي، عرض أقل من القطاعي، جملة أقل من القطاعي، وحد جملة مطلوب (٢+) عند وجود سعر جملة وممنوع بدونه.
- إضافة عرض أو حذفه تُحدّث وسم `offer` تلقائيًا حتى تظهر البطاقة في «عروض» المتجر.
- **الفارغ في خانات الأسعار «غياب» لا «صفر»**: حفظ خانة فارغة يكتب `null`، و`toNumber` في `src/utils/pricing.js` يعامل `null` والفراغ كعدم وجود (`Number(null)` يساوي صفرًا، فالخطأ هنا كان يولّد «عرضًا» بـ 0 ج.م وسعرًا صفرًا على بطاقة الصنف). صنف بغير عرض ولا جملة يبقى قطاعيًا كما هو، وصفحته تكتب «جملة — غير متاح لهذا الصنف».
- **الصنف كامله بلا سعر حالة صريحة مش صفر**: أصناف بخور تيجاني (DL-1101…DL-1111) وصنفا بخور شعبي (DL-1301، DL-1302) وأصناف بخور ناموس (DL-1401…DL-1404) مخزّنة بـ `retailPrice: null` و`stock: null` لأن التاجر لم يُعتمد أسعارها بعد. عندها `priceForQuantity` ترجع `unit: null` مع `basis: 'unset'` («بلا سعر» في `BASIS_LABELS`)، و`formatPrice(null)` يكتب «—» بدل «0 ج.م»، والبطاقة وصفحة الصنف يقولان «السعر يُحدَّد» و«وحدة البيع لسه بتُحدَّد»، و`availabilityOf` ترجع `key: 'unknown'` («المخزون غير محدَّد») فلا تُخلط مع «نافد»، وزر الإضافة يقف معطلًا برسالة «السعر لسه ما اتحدّدش». `buildCartLines` **تُسقِط** السطر بلا سعر بدل أن يجمّع على صفر (صفر مختلق أخطر من سطر ناقص)، و`sanitizeItems` في السلة و`rejectionOf` فيها ترفضان الصنف اللي فقد سعره بعد ما اتحفظ، و`clampQuantity` مع `stock: null` لا تُلغي الحد بل تترك الكمية، و`quantityOptions` تتجاهل سقفًا غير مكتوب، وفلاتر السعر في `/products` تستبعد البلا سعر (و«بلا» مش «أقل من») والترتيب بالسعر ينزلها آخر القائمة في الاتجاهين، و`cheapestByCategory` في اللوحة يتخطاها حتى لا تصير «أرخص صنف» صفرًا، وتصدير الجرد CSV يترك خانة المخزون فارغة ولا يكتب صفرًا.
- الصور المتاحة في اللوحة هي صور المشروع المحلية فقط (SVG مضمّن)، ولا تُقبل روابط خارجية، ولا تُرفع أي صورة إلى أي خدمة.
- اللوحة local-only: لا خادم ولا قاعدة عملاء، والتنبيه مكتوب أسفل كل تبويب. أرقام هواتف الطلبات التجريبية placeholders، وحقول تواصل الشركة (`phone`/`whatsapp`/`email`/`hours`) ما زالت `null` إلى أن تعتمد الشركة قيمها.
- **المخزون لا يُخصم من الطلبات**: أرقام `stock` مصدرها `src/data/products.js` وتعديلات التاجر فقط، وتسجيل طلب أو تغيير حالته لا يغيّرها. اللوحة تنبّه بذلك صراحة في «نظرة عامة» (تحت حالة الكتالوج وفوق التنبيهات) وفي تبويبي المنتجات والطلبات، فالأرقام مؤشرات عرض لا جرد فعلي للمخزن.

### التوصيل وحد الجملة (src/utils/delivery.js)

- أربع قواعد قابلة للتعديل محفوظة في `localStorage` بمفتاح `delta-store:delivery-rules`: `feeLocal` و`feeOther` و`freeFrom` و`wholesaleMin`. القيم الافتراضية تجريبية (15 / 25 / 1500 / 300 ج.م) واللوحة تسمّيها صراحة قيمًا تجريبية؛ لا يدّعي المشروع أنها رسوم الدلتا الفعلية.
- `deliveryQuote({area, subtotal})` يحسب المقابل: النطاق القريب هو ما احتوى «دمياط» أو «الزرقا» (الزرقا مركز تابع لدمياط)، وأي محافظة أخرى تدخل في «باقي المحافظات»، وتجاوز `freeFrom` يحوّل البند إلى «توصيل مجاني / بلا مقابل». **بلا محافظة مختارة لا يوجد تقدير**: تُرجَع `null` بدل اختراع رقم، والواجهة تقول «اختر المحافظة أولًا ليظهر بند التوصيل».
- `freeFrom = 0` يعني بلا إعفاء، و`wholesaleMin = 0` يعني بلا حد أدنى — والصفر في الحقلين قيمة صحيحة مقصودة وليس غياب قيمة.
- حد الجملة يمنع التسجيل فقط عندما يكون في السلة صنف محسوب بسعر الجملة فعليًا (`line.basis === 'wholesale'`)؛ الطلب القطاعي لا يُرفض لقصوره عن الحد، بل تظهر له ملاحظة «ناقصك لسعر الجملة» كما كان.
- البند يُلتقط كلقطة داخل الطلب لحظة الإنشاء (`sanitizeDelivery`)، و`payableOf(order)` يجمع إجمالي الأصناف والوحدات والمقابل والمبلغ المطلوب. التعديل اللاحق للقواعد لا يغيّر الطلبات الصادرة، والطلبات القديمة تُقرأ بمقابل صفر.
- السلة تعرض تلميح الإعفاء بحالتينه: «ناقصك X للتوصيل المجاني» قبل الحد، و«تجاوزت الحد: التوصيل بلا مقابل عند اختيار المحافظة» بعده.

### العدّ داخل اللوحة (src/utils/stockCount.js)

- التاجر يعدّ فعليًا ويكتب العدد في عمود «العدّ»؛ «تسجيل» يحفظ العدد في سجل منفصل بمفتاح `delta-store:stock-counts` **ولا يمس رقم المخزون إطلاقًا** — احترامًا لقاعدة أن المخزون لا تتحكم به الطلبات.
- «اعتماد في المخزون» هو وحده الذي يكتب في خانة `stock`، وبيخطوة تأكيد (الزر يتحوّل «اعتماد N» + «إلغاء») وبعدها يظهر تاريخ الاعتماد والفارق يصبح صفرًا. الاعتماد يكتب العدد المعدود نفسه لا الفارق.
- «مسح العدّ» يحذف القيد ويترك المخزون كما هو؛ وسجل العدّ لا يرجّع أي صنف لقيمته القديمة. الفارق يُحسب من المكتوب لحظة العرض (`diffFor`)، وصفحة اللوحة وحدها تعرضه — العميل لا يرى العدّ ولا الفارق.
- العدّ يقبل الأرقام العربية ويرفض الفراغ والإشارة السالبة وغير الرقمي (فراغ ≠ صفر)، والكسور تُقرَّب لأسفل. أي قيد تالف في التخزين تتجاهله القراءة الآمنة، و`reloadStockCounts()` يعيد تحميل السجل من `localStorage` بدون إعادة تحميل الصفحة.
- ملخص الجرد فوق الجدول: عدد الأصناف عليها عدّ مسجَّل، وكم منها بانتظار الاعتماد، وكم عليه فارق، وكم لم يُعدّ بعد — والكل ينصّ على أن الأرقام تبقى في المتصفح وحده.

### موقع الصنف في المخزن (`location`)

- حقل `location` على الصنف = مكان الرف داخل المخزن، نصّي بحد ٢٤ حرفًا («رف B3»، «عنبر D1») ومطبوع في `src/data/products.js` بقيم تجريبية للأصناف الثلاثة عشر القديمة المعتمدة الأسعار؛ أصناف تيجاني الأحد عشر وإنسام الاثنين والعشرين `location: null` لأن مكانها في المخزن لم يُحدَّد بعد.
- داخلي بالكامل: يظهر في عمود «المكان» بلوحة المنتجات وفي نموذج الإضافة/التعديل وفي بحث اللوحة وفي عمود «مكان الصنف» بملف الجرد وفي خانة «المكان» بورقة التجهيز. **لا يظهر أبدًا** في صفحة الصنف أو بطاقات المتجر أو السلة أو الفاتورة.
- تعديل مكان الصنف يمرّ عبر قائمة الحقول البيضاء في `catalogStore`، فملف البذرة لا يتغيّر و«استرجاع البيانات الأصلية» يرجّعه.

## تتبع الطلب برقم التليفون

- صفحة `/track` أصبحت تبحث **برقم التليفون** بدل رقم الطلب: تكتب الرقم (بمسافات أو شرطات أو أرقام عربية) فتظهر كل الطلبات المسجّلة عليه.
- رقم لطلب واحد يعرض مراحله مباشرة، وأكثر من طلب يعرض قائمة (الحالة والإجمالي) وزر «عرض المراحل» لكل طلب.
- الأرقام التجريبية الجاهزة في `src/data/orders.js` أرقام موضوعة للعرض (`01000000001` وما شابه) — ليست أرقامًا حقيقية، وأسماء المحافظات فيها أسماء محافظات حقيقية مع عنوان نصّه «عنوان تجريبي للعرض».
- روابط `/track?number=DL-…` القادمة من صفحة التأكيد أو اللوحة أو الفاتورة ما زالت تعمل وتفتح تفاصيل طلب واحد.
- منطق المطابقة `ordersForPhone` في `src/utils/checkout.js`، ويطبّع الرقم بنفس تطبيع أرقام البحث العربي.

## شكل الأقسام والفلاتر

- **خريطة الأقسام كما أملاها التاجر** (`src/data/categories.js`): **١٦ قسمًا رئيسيًا** — البخور، الولاعات، ملمعات الأحذية، ماكينات الحلاقة، اللواصق، **حجائر**، **ميدالية ومحفظة**، **مواد سريعة الاشتعال**، **أعياد ومناسبات**، **خلة وسلاكة**، أكياس شامبو وجل، **عناية الاسنان**، **عناية منزلية**، **أدوات مكتبية**، **ألعاب أطفال**، **أدوات كهربائية** — و**٣٠ قسمًا فرعيًا** بـ `parent` (**٤٦ قسمًا في المجموع**)، **وقد ينفرع الفرعي مرة ثالثة بل رابعة**: تحت الفحم (أقراص سريعة الاشتعال، مكعبات فحم)، تحت عناية الاسنان (سيجنال، كلوزاب)، تحت عناية منزلية (مشبك غسيل، نفتالين، لزقة فار، استك ملابس، استك فلوس)، وتحت بخور إنسام قسم «هرمي» ينفرع لثلاث درجات، وتحت البخور **أربع عائلات** كل واحدة بأقسامها:
- **دمج «مواد سريعة الاشتعال»** (2026-10-31): أمر التاجر «الكبريت والغاز والفحم يبقى اسمها مواد سريعة الاشتعال»، ولما عرضنا عليه الأشكال اختار **الأسماء التلاتة تفضل أقسامًا فرعية تحت القسم الجديد** (`flammables` أب لـ `matches`/`charcoal`/`gas`) — مش دمجًا يسوّيهم. يعني **ما اتشالش اسم ولا تحرّك صنف**: الأصناف الخمسة (`DL-3001`…`DL-3003` كبريت، `DL-4001` مكعبات فحم، `DL-4002` فحم شواء) على أقسامها كما هي، وشجرة الفحم الفرعية ورا أبوها في مستوى ثالث، و«الغاز» لسه بلا أصناف. وصف القسم الجديد **سطر رتّبناه من أوصافه التلاتة** اللي أملاها (كبريت أمان ومطبخي وعازل للرطوبة + فحم المعسل والشواء ومواد الإشعال + غاز التعبئة والأسطوانات الصغيرة) وهو مطلوب يصححه أو يملّي سطره. **نتيجتان لازم يعرفهم**: مسار أي صنف في المجموعة بقى يبدأ من «مواد سريعة الاشتعال» (لوحة وتصفح وفاتورة وCSV)، و«أصناف مشابهة» لكبريت بقى يجيب فحم كمان — لأن الجوار = ورقة الأب، والأب بقى كبيرًا.
- **اعتماد الخريطة ذات الستة عشر قسمًا** (2026-10-31، بعد الدمج بساعة): التاجر أعاد إملاء الأقسام الرئيسية بنفسه وقال «هتشيل بقا الاقسام اللي موجودة… هنعتمد دا» و«هتسيب اللي جوا قسم البخور واللي جوا مواد سريعة الاشتعال واللي جوا عناية الاسنان وعناية منزلية». نُفّذ حرفيًا: **خمسة أسماء تتصحح إملائيا** (الحجائر ← **الحاجاير** ← **حجائر** (صححها مرة تانية في نفس اليوم: «الحاجاير مكتوب غلط، اسمها حجائر»)، ميداليات ومحافظ ← **ميدالية ومحفظة**، خله وسلاكة ← **خلة وسلاكة**، عناية الأسنان ← **عناية الاسنان**، عناية منزلي ← **عناية منزلية**)، وثلاثة أقسام رئيسية **جديدة بأسمائها فقط** بلا أصناف وبلا وصف ملّاه التاجر (أدوات مكتبية، ألعاب أطفال، أدوات كهربائية — وصفها المؤقت «أصناف هذا القسم تُحدَّد من التاجر.»)، و**«أعياد ومناسبات» قسم رئيسي جديد ونزل «البالون» قسمًا فرعيًا تحته** لأنه كان رئيسيًا فصار ابنًا — هو اللي اختاره لما سألناه («يتحط ف قسم اعياد ومناسبات»). **ما اتشال قسم ولا صنف ولا اتبدل معرّف**: الأرقام `DL-…` على أقسامها كما هي، وشجرة البخور (١٨ قسمًا) ومجموعة الاشتعال (٦) وسيجنال/كلوزاب وخمس أوراق عناية منزلية ما تحرّكتش، والمعرّفات (`hajayer`, `medals-wallets`, `khella-selaka`, `dental-care`, `home-care`, `balloons`) فضلت زي ما هي عشان Overrides التاجر في اللوحة ومسارات الأصناف ما تنقطعش. «مفيش أقسام ناقصة — ١٦ بس» كما قال، فترتيب الشريط هو ترتيب إملائه بالضبط.
- **صور الأقسام التي أملاها التاجر (2026-10-31)**: على دفعتين — ست صور أول النهار («ضفهم بقا كصورة ف الاقسام عشان العميل يعرف شكل المنتج») ثم العشرة الباقية («هضيف الصورة دي في باقي الاقسام») — مسكونة محليًا في `src/assets/categories/<معرّف القسم>.jpg` (بلا روابط خارجية) تحت حقل **`image`**. **الاسم مساوي معرّف القسم بالظبط** فالاتفاقية واضحة والاختبار بيثبتها. **القاعدة في `src/utils/sectionOrb.js`** — `orbSourceOf(category, items)` بتفضّل **صورة القسم** التي ملّها التاجر، وإلا `coverProductOf(items)` = أول صنف **له صورة** (والأكثر طلبًا لو مصوَّرًا)، وإلا `src: null` فتترسم أيقونة القسم في الدائرة. **ما بنخترعش صورة لقسم بلا صورة، وما بنعرضش صورة صنف بلا صورة على أنها شكل القسم.** **والأقسام الفرعية (٣٠) كلها بلا `image`** — ما بنحطش صورة لقسم ما ملّاش صاحبها، والورقة اللي عليها أصناف لسه تاخد صنفها الممثل والفاضية تقول «لا أصناف في هذا القسم بعد». **نتيجتان من الصور:** «حجائر» = **بطاريات** (أسطوانات/كشافات)، و«خلة وسلاكة» = **أعواد قطن وسواك الأسنان** — لكن **الوصف المعروض للعميل لسه «أصناف هذا القسم تُحدَّد من التاجر.»** لأنه ما ملّاش نصّه، فنحن ما بنصوغش من الصورة. **وأخيرًا — المقاس بقى دائرة**: من 2026-10-31 صورة القسم تتعرض **دائرية** على البطاقة وفي شريط `/products` (`ratio='square'` + `border-radius: 50%`)، والقاعدة `orbSourceOf` في `src/utils/sectionOrb.js` وحدها بتقرّر المصدر. العشر الصور المربعة أو شبه المربعة (من 554×554 إلى 1500×1500 بنسب 0.88–1.09) ما بتتقصّش منها حاجة في `cover`، **بس الدائرة تاكل أركانها** — يعني أي حاجة في أركان الإطار (أسعار مطبوعة، حواف رف) بتروح. خلة وسلاكة 960×1093 تتقصّ من **أعلى وأسفل** قبل الدائرة. والأربع الأعرض من 1:1 (أعياد 1408×768، أدوات مكتبية 640×360، عناية الاسنان 715×429، عناية منزلية 538×360) **بتخسر أكثر من قبل**: `cover` في مربّع يقطع لها ما يقارب **نصف العرض** (الأربعاء 640×360 ← 360×360، أي 44% من العرض) وفوق كده الدائرة تقص الأركان، فالموضوع المهم في الصورة لازم يبقى في نصّها بالظبط. والصور الصغيرة (عناية منزلية 538×360، أدوات مكتبية 640×360، عناية الاسنان 715×429) هتبان **ناعمة** على شاشات 2x — والدائرة بتفضح النعومة أكثر من المستطيل لأن عين العميل بتوقع حوافها.
- **صورتا الإعلان اتشالت من العرض (2026-10-31)**: من الستة عشر اللي ملّها، **أربع عشرة على البطاقات** و**اتنتين بطلت `image`** — «البخور» (`incense`) و«مواد سريعة الاشتعال» (`flammables`). السبب إن الاتنتين **ليستّا صور أصناف بل بوستَري دعاية لشركة تانية**: صورة البخور بوستر إنسام نفسه بشعاره وادعاءاته المطبوعة («أكثر من 58 منتج»، «يتم تصديره إلى أكثر من 15 دولة»)، وصورة الاشتعال إعلان «جلوب الاشتعال المتكاملة / Universal Ignition Group» (مع Cheetah وGaslighter وفحم الشعلة وأسيرة). عرضهما على بطاقات الدلتا **ادّعاء كلام لغيرنا**، وهو ضد قاعدته. **وما اتشال ملف**: `incense.jpg` و`flammables.jpg` باقيان في `src/assets/categories/` كما هما (ونسختهما في `src/assets/categories/originals/`)، والتغيير `image: null` في `categories.js` وحده — فالبطاقات والشريط رجّعوا تلقائيًا لقاعدة `category.image ?? صورة صنف ممثل` وبتعرض الآن **صنفًا ممثلًا من أصناف القسم نفسه** (علبة أعواد بخور للبخور، وعلبة كبريت أمان للاشتعال) داخل دائرة بنفس مقاس باقي الأقسام، وبلا صورة مكسورة. والبناء ما بقاش يشحن الملفين: **حوالي 343 كيلوبايت اتشالت من `dist/assets`**، و`originals/` ما دخلش في الحزمة أصلًا لأن مفيش منه استيراد.
- **ليه ما اخترناش التجميل بالبكسل، وقراره في الباقي**: جرّبنا فعليًا على `flammables.jpg` مسحًا موضعيًا محليًا (موزاييك بكتل، ثم ضبابة ثلاثية على إحدى عشرة منطقة) — النص بقى غير مقروء فعلًا، **لكن كيس الفحم وعلبة الكبريت والأعواد اتحوّلا لخطوط وبانّت حواف المستطيلات**، فالنتيجة مرفوضة والملف رجّعناه **بايت-بايت** من `originals/` (تحققنا بـ`cmp`). **وصورتا «الولاعات» و«ميدالية ومحفظة» سيبتاهم زي ما هما**: دول صور بضائعه الحقيقية والشعارات مطبوعة على المنتج نفسه — مش دعاية شركة تانية — فنزعها بالبكسل يفسد صورة البضاعة بلا فايدة. **بس القرار له**: صورة الولاعات فيها علامات (Zippo، Cricket، BIC، Tiger) و**مونوغرام يشبه LV**، و«ميدالية ومحفظة» فيها **شعارات سيارات** (BMW، Mercedes، Toyota، Ferrari، Audi، D&G)؛ لو اختار يمسكها من البطاقة يبقى `image: null` زي الاتنتين الأوليين، ولو ملّاه صورة تانية نضيفة يتبدّل الملف في نفس المجلد وحقل `image` فقط. **وفيك** صورة «ماكينات الحلاقة» فيها **موس يدوي** لا ماكينة، وصورة «عناية الاسنان» **أدوات حمّام عامة** (فوطة وصابون ولوشن) وفيها فرشتين بس — دول كمان مستنيين كلمة منه.
- **بخور تيجاني** — أربع أقسام كما أملاها: **أعواد** و**هرمي** و**كرتونة متنوعة** و**بودر أكياس**.
- **بخور إنسام** — **ستة أقسام** كما أملاها: **أعواد** و**هرمي** و**بودر أكياس** و**استاند** و**مكعبات** و**أريلاكس**، و«هرمي» اللي جواه **ثلاث درجات**: **مخروطي** و**وسط** و**غالي**. يعني الشجرة هنا بلغت **أربعة مستويات** (البخور › بخور إنسام › هرمي › مخروطي) — الدوال تقرأ `parent` بلا حد مكتوب للعمق، والفلاتر والـ `optgroup` والمسار والشارة كلهم بيتعاملوا مع أي عمق، و`categories.test.js` ماسك السقف عند أربعة. (درجات الهرمي كانت أول ما دخلت أقسامًا أشقاء بأسمائها الكاملة «هرمي مخروطي/وسط/غالي»؛ التاجر صححها لتعشيق تحت «هرمي» فاتنفّذ التصحيح.) ودرجة «مخروطي» بقى فيها **صنف واحد باسم الدرجة** («مخروطي» بـ590) بعد ما أمر التاجر يدمج الأصناف الثمانية عشر اللي كانت فيها، فصار عدّ «هرمي» ٩ لا ٢٦.
الأسماء منسوخة كما أملاها التاجر — وإملاء الخريطة الجديدة («حجائر»، «ميدالية ومحفظة»، «خلة وسلاكة»، «عناية الاسنان» بلا همزة) معتمد **حرفيًا** كما كتبه، حتى لو خالف تصحيح الهمزة اللي اعتمده سابقًا — و«حجائر» نفسها صحّحها مرة تانية من «الحاجاير» فبقت كما كتبها ثانيًا (بلا ألف ولام). **اسم واحد مازال على حرفين:** كتبه في القائمة «عناية منزلي» وفي الكلام «عناية منزلية»، فالمعمول به الآن **عناية منزلية** (الأقرب للإملاء الأول والألف الممدودة هي القاعدة في باقية الأسماء) — كلمة منه تثبّتها أو ترجّعها. وأقسام «حجائر» و«خلة وسلاكة» و«استك» كانت تنتظر توضيح محتواه — **صوره اللي أرفقها يوم 2026-10-31 كشفت الأولين** (حجائر = بطاريات أسطوانات/كشافات، وخلة وسلاكة = أعواد قطن وسواك الأسنان)، لكن **الوصف المعروض للعميل لسه «أصناف هذا القسم تُحدَّد من التاجر.»** لأنه ما ملّاش نصّه، فنحن ما بنصوغش من الصورة.
- **بخور شعبي** — قسم **بلا أقسام فرعية**، جواه **صنفان** بالاسمين اللي أملاهما التاجر: **بخور الشربيني** (`DL-1301`) و**بخور شعبي** (`DL-1302`)؛ قال «طالع منوا حاجتين» فقُرئت صنفين لا قسمين، وهو اللي أكّده. صنف يحمل اسم قسمه بالظبط زي ما صنف «مخروطي» يحمل اسم درجته. أملى الأسماء بس، فماخدش سعر ولا عبوة ولا مخزون ولا صورة — `retailPrice: null` يعني «السعر يُحدَّد» وزرّ الشراء متعطّل، و`stock: null` يعني «المخزون غير محدَّد»؛ القرار نفسه اللي اتاخد في بخور تيجاني. السلسلة `DL-13xx` مخصوصة له.
- **بخور ناموس** — العائلة الرابعة تحت البخور، و**ورقة مباشرة** مثله زي «بخور شعبي» (بلا أقسام فرعية). «جواه أربع حاجات» اتقرئت **أربع أصناف** لا أربع أقسام — وهو اللي اختاره التاجر لما سألناه، تطابقًا مع قراره في شعبي: **أعواد لوجينا** (`DL-1401`) و**أقراص الصفا** (`DL-1402`) و**سائل جهاز الناموس** (`DL-1403`) و**جهاز الناموس** (`DL-1404`). ولا واحد فيهم سعر أو عبوة أو مخزون أو صورة — ما ملّاش غير الأسماء، فالعدّاد «4 صنف» والشراء متعطّل لحد ما يملّي. لاحظ إن ده أول حاجة في البخور مش بخور بالمعنى المعتاد (جهاز وسائل ناموس)، ووصف قسم البخور المعروض للعميل لسه «أعواد وأقماع وقطع بخور للتدخين والتعطير» — التاجر ما ملّاش تعديل له فما اتغيّرش.
- الدوال المشتركة في نفس الملف حتى لا تُكرَّر القواعد في المكوّنات: `topCategories` و`subCategories` و**`categoryChain`** (السلسلة من الرئيسي حتى العقدة نفسها، تصعد بـ `parent` وتوقفها مجموعة `seen` فلا دورة) و**`categoryChainNames`** (أسماء السلسلة، يستعملهم البحث فيطابق «تيجاني» و«أعواد») و`rootCategory` (= أول السلسلة) و`categoryGroupIds` (أي مستوى يجمع كل ما تحته بأي عمق، والورقة تبقى على نفسها) و`categoryNeighborhoodIds` (جيران الصنف = ورقة المجموعة التي يقف عليها قسمه مباشرة، فصنف «أعواد» يجاور باقية تيجاني لا كل البخور) و`categoryLabel`/`categoryPathLabel` (التسمية المختصرة والمسار «البخور › بخور تيجاني › أعواد») و**`sectionRail(selectedId)`** (ورقة الشريط الجانبي الدائري: `{ scope, crumbs, items }` بمستوى واحد لكل اختيار) و**`sectionCount(id, productCount)`** — يرجّع `{ value, unit }` للعدّاد المعروض، وقاعدته عند التاجر: **كل مستوى يعدّ اللي جواه على طول**. القسم اللي تحته أقسام يعدّ **أقسامه المباشرة** (البخور «4 قسم» = عائلاته الأربع، لا أصنافها التسعة والتلاتين)، والورقة اللي ما تحتهاش أقسام تعدّ **أصنافها** («بخور ناموس 4 صنف»، «أعواد إنسام 6 صنف»). قسم بلا أصناف **وبلا أقسام** (حجائر، الأدوات المكتبية، ألعاب أطفال، أدوات كهربائية) يفضل «0 صنف» لأنه فعلًا فاضي — والتفريق في `unit` المعروض نفسه وفي `title` على شريط الفلاتر، مش في رقم وحده. **استثناء لازم تعرفه:** القسم اللي عليه أصناف **بنفسه** ومعاها أقسام (عناية منزلية: ٥ أصناف على الأب و٥ أقسام فاضية، والفحم: صنف على الأب) يعدّ أقسامه، فأصنافه ما بتدخلش في الرقم — لسه بتبان في الفلترة وفي مدى الأسعار على بطاقته. ومن الدمج الجديد «مواد سريعة الاشتعال» يعدّ **3 قسم** (كبريت/فحم/غاز) رغم إن تحتها ٥ أصناف، و«الكبريت» بقى ورقة فيعدّ **3 صنف**، و«الغاز» ورقة فاضية فـ**0 صنف**. ومن الخريطة الستة عشر: «أعياد ومناسبات» أب لورقة واحدة فعدّه **«1 قسم»** رغم إنه بلا أصناف خالص، و«البالون» تحته فصار **«0 صنف»** بدل ما كان رئيسيًا.
- بطاقات الأقسام (`CategoryCard`) صارت بطاقة كاملة: **دائرة صورة** — صورة القسم التي ملّها التاجر إن وجدت، وإلا صورة صنف ممثل من جوه، وإلا مربّع فارغ — بأيقونة القسم ملتصقة بحافة الدائرة من تحت، عدد الأصناف، مدى الأسعار المحسوب فعليًا من بيانات المنتجات، ورابط «تصفّح القسم»، ثم روابط الأقسام الفرعية التي تفلتر على القسم الفرعي وحده. **الدائرة مكانتش مستطيل 4:3**: من 2026-10-31 `.category-tile__media` بقى غلافًا وسطيًا و`.category-tile__orb` عرضه `clamp(104px, 46%, 150px)` والصورة `ratio='square'` بـ `border-radius: 50%` (والأيقونة `inset-inline: 0; margin-inline: auto` — مش `inset-inline-start: 50%`، راجع بند الممرّ الدائري تحت). العدّاد يطلع من `sectionCount` فالشيبس بيكتب الرقم **ووحدة العدّ** معاه: «4 قسم» للبخور (عائلاته الأربع) و«2 صنف» لبخور شعبي (ورقة) و«5 قسم» لعناية منزلية. القسم بلا أصناف يعرض «لا أصناف في هذا القسم بعد» بدل صورة مكسورة — وهذا حال **١٢ من الأقسام الرئيسية الـ١٦** حتى تُعبَّأ من اللوحة، منها **عشرة بلا أقسام فرعية فعدّها «0 صنف»** واثنان («أعياد ومناسبات» و«عناية الاسنان») فيهما أقسام فعدّهما «1 قسم» و«2 قسم» (وما بقتش بطاقات الكبريت والفحم والغاز ثلاث بطاقات؛ البطاقة الوحيدة هي «مواد سريعة الاشتعال 3 قسم» وأبناؤها الثلاثة يظهرون روابط تحتها، ونزلت بطاقة البالون من الرئيسية فصارت رابطًا تحت «أعياد ومناسبات»). الرئيسية وصفحة `/categories` تعرضان الأقسام الرئيسية فقط (**١٦ بطاقة**)، والفوتر يكررها في عمودين. **ونتيجة الفلتر الصارم**: رابط «تصفّح القسم» على بطاقة أب (البخور، مواد سريعة الاشتعال، أعياد ومناسبات…) يودّي لصفحة المنتجات على القسم نفسه، فلو ما عليه أصناف مباشرة تظهر حالة الإرشاد بأبنائه (مش شبكة فاضية ولا أصناف مختلقة) — وأبناء البطاقة يبقا روابط مباشرة تحتها زي ما هم.
- **شريط الأقسام الدائري (`SectionRail`) — 2026-10-31**: أمر التاجر «الشجرة اللي في المنتجات والمنتجات تظهر بالعرض… والعميل يختار مثلا البخور فيفتح البخور وفي الجنب الشريط بتاعها ويختار بقا أي قسم عايزه، والصور اللي في الأقسام تبقى صور برده المنتجات وتكون في شكل دائرة». **المنطق في `sectionRail(selectedId)`** (`src/data/categories.js`) بيردّ **مستوى واحدًا لكل اختيار** لا شريطًا لكل مستوى: `{ scope, crumbs, items }` — القسم المختار اللي تحته أقسام يعطي **أبناءه**، والورقة اللي مفيش تحتها أقسام تعطي **إخوتها في أبيها** (`scope` يبقى الأب)، ومن غير اختيار أو مع رئيسي بلا أبناء (حجائر) يرجع **للأقسام الرئيسية الستة عشر**. ليه مستوى واحد: شريط لكل مستوى كان هياكل ~400px من الشاشة على عمق أربعة (البخور › إنسام › هرمي › مخروطي) — فالممرّ `catalog-crumbs` فوق الشريط هو اللي يطلع خطوة بخطوة («كل الأقسام › البخور › بخور إنسام › هرمي» والشجرة العميقة كلها باينة فيه)، والشريط وحده هو اللي يبقى تحت الممرّ جنب المنتجات. المكوّن (`src/components/category/SectionRail.jsx`) يفتح بـ**دائرة «كل <الأب>»** أيقونتها `LayoutGrid`، وبعدها دائرة لكل قسم صورتها من `orbSourceOf` + عدّاد `sectionCount` (الرقم وحده في الشارة، والوحدة في `title`)، والاختيار بيتغيّر **بالرابط** وحده فما فيش حالة مكرّرة تنقطع بالريديريكت. **رابط الشريط من `catalog.hrefFor({ category })`** في `useCatalogQuery.js` — بيكتب/بيشيل مفتاحًا واحدًا على `searchParams` القائمة، فالبحث وحدّ السعر والترتيب **ما يسقطوش** لما العميل يغير القسم (اتأكد حيًّا: `?q=ولاع&min=20&sort=price-asc` + ضغطة على الولاعات ← `…&category=lighters` و3 أصناف وخانة البحث لسه «ولاع»). الشريط اتحطّ كمان فوق بطاقات `/categories` بـ`title='اختر قسمك'` و`showAll={false}` (البطاقات دي واجهة قراءة لا فلتر، فمفيش «كل الأقسام» تبقى نشطة غلط). **ودائرتان تحت البخور بترجعان لأيقونة القسم مش صورة** — بخور شعبي وبخور ناموس أصنافهم `image: null` (ومعهم دائرة «كل البخور» نفسها أيقونتها `LayoutGrid`) — فما فيش صورة صنف نعرضها، والأمانة تقتضي أيقونة لا صورة مخترعة.
- صفحة `/products` مقسومة إلى عمودين (`src/pages/Products.jsx` + `.catalog-layout`): عمود 280px للفلاتر وعمود رئيسي للشبكة. الفلاتر قائمة عمودية فيها عدد الأصناف لكل قسم ولكل وسم، وتثبت أثناء التمرير (`sticky`). **دي لوحة الفلاتر — لا شريط الأقسام الدائري اللي فوق الشبكة (بنده فوق)**. **الشريط يعرض الأقسام الرئيسية الستة عشر في حالته المغلقة**؛ ما تحتها لا يظهر إلا لما تضغط السهم الجانبي (`ChevronLeft` مغلق ← `ChevronDown` مفتوح). الصف الفرعي مكوّن `FilterNode` **استرجاعي** (`filter-group` داخل `filter-group`) بنفس المنطق على أي مستوى، فيبقى الشريط قصيرًا بدل تمرير طويل، والمستوى الأعمق ينزاح أكثر بجانبه (`--sub-level` محسوب من `depth` ويضرب في `calc`) ليظهر أبوه المباشر — ركن ضروري لمّا بقت درجات هرمي إنسام مستوى رابعًا فوق بعضها. الحالة المفتوحة مجموعة `Set` من معرّفات (`openIds`) لا جذرًا واحدًا، فيمكن فتح البخور والفحم معًا؛ واختيار قسم فيه أقسام تحته يفتحهم فورًا، والرابط المباشر `?category=incense-tijani` كمان يفتح أباه (تمييز الممرّ `is-trail`) وفتوحاته (`pickedOpenIds ?? ...` — محسوب أثناء العرض بلا `useEffect`، فالحالة المشتقة من الرابط تظل هي الأصل قبل أول تدخّل). عدد الصف الرئيسي **عدّاد اللي جوّه** عبر `countByGroup` + `sectionCount`: الأب اللي تحتها أقسام يظهر عدد أقسامه، والورقة تظهر أصنافها — فالبخور «4» وتيجاني «4» وإنسام «6» و«هرمي» «3»، بينما «مخروطي 1» و«وسط 5» و«غالي 3» و«ناموس 4» أصناف — ومن بعد الدمج «مواد سريعة الاشتعال 3» (كبريت وفحم وغاز) و«الكبريت 3 أصناف» تحتها. شارة العدّاد (`filter-option__count`) تعرض الرقم وحده عشان المساحة ما تتقطعش، والـ `title` يكتب الوحدة («4 قسم» / «6 صنف»). **والفلترة بقت صارمة على القسم نفسه** (2026-10-31 بأمر التاجر «يعمل فلتر للمنتج اللي واقف عليه بس»): `?category=incense` يجيب الأصناف المسكّنة على البخور **مباشرة** وحدها — وهي **صفر** لأن أصنافه كلها في العائلات الأربع — فتظهر حالة إرشاد «البخور» قسم بأقسامه بروابط أبنائه بدل ٣٩ كرتًا كانت الشجرة بتجمعها (الفلتر في `sectionFilterIds`، والقسم الأب اللي عليه أصناف بنفسه زي «عناية منزلية» لسه يعرض أصنافه الخمسة وأبناءه في الشريط). العدّاد في الشريط وفي الشجرة لسه يوصّف المشجر («4 قسم»)، وده اللي بيوجّه النزول. عند عرض 1000px فأقل يرجع التخطيط عمودًا واحدًا ويُلغى التثبيت.
- في اللوحة: شيبسات القسم في تبويبي المنتجات والتسعير رئيسية فقط بعدد المجموعة، وفي المنتجات الرقم **بوحدته** من `sectionCount` — «البخور (4 قسم)» و«عناية منزلية (5 قسم)» و«حجائر (0 صنف)» — لأن العدّاد بقى يوصّف المشجر لا الكمية؛ وعمود «القسم» وعنوان الصف في التسعير يكتبان المسار كاملًا («البخور › بخور تيجاني › أعواد»)، ومحرر الأصناف يعرض الأقسام في `optgroup` واحد لكل قسم رئيسي لأن HTML لا يُعرِّش المجموعات — فعمق الفرع يُرسم ببادئة «— » محسوبة من `categoryChain`، والخيار الأول في كل مجموعة هو القسم الرئيسي نفسه. تصدير الجرد CSV يكتب المسار كاملًا في عمود القسم، وبحث اللوحة والبحث في المتجر يطابقان اسم القسم الفرعي والرئيسي معًا.
- صفحة الصنف: مسار تنقّل يمشي السلسلة كلها (الرئيسية ← المنتجات ← البخور ← بخور تيجاني ← أعواد) وكل عقدة فيها رابط يفلتر عليها، وشارة القسم على بطاقة المنتج تكتب **العائلة + الورقة**: في السلسلة الثلاثية فما فوق تاخد `chain[1]` مع آخر عقدة، وفي الثنائية والأحادية تبقى السلسلة كما هي. فالنتيجة «بخور تيجاني › أعواد» مقابل «بخور إنسام › أعواد» — ضروري لأن في تيجاني وإنسام قسمًا اسمه «أعواد» وقسمًا اسمه «بودر أكياس» — و«بخور إنسام › مخروطي» لدرجة الهرمي، من غير ما تكتب «هرمي › مخروطي» فتضيّع اسم العائلة ولا «بخور إنسام › هرمي › مخروطي» فتطوّل الشارة. وفي الأقسام الثنائية تبقى الشارة أبًا ثم ابنه («مواد سريعة الاشتعال › الكبريت» بعد الدمج، و«عناية الاسنان › سيجنال»)، وللقسم الرئيسي اسم واحد («الولاعات»، و«أعياد ومناسبات» صار أبًا لـ«البالون» فالشارة تبقى «أعياد ومناسبات › البالون»)، و«الفحم › مكعبات فحم» فضلت كما هي رغم إنها بقت ثلاثية لأن `chain[1]` هو الفحم نفسه. و«أصناف مشابهة من نفس القسم» تجاور ورقة المجموعة التي يقف عليها القسم، فصنف «مخروطي» يجاور درجات «هرمي» التلات تحت أبوها (و«هرمي» تيجاني له مجموعة لوحده)، وصنف «أعواد» يجاور باقية إنسام — ومن بعد الدمج صنف «الكبريت» يجاور أصناف الفحم لأنه صار ابنًا وأبوه المجموعة الكبرى.
- عند عرض 1000px فأقل يرجع التخطيط عمودًا واحدًا ويُلغى التثبيت، فلا تضيع المساحة على الهاتف.

## المتجر على الهاتف

القياسات دي متأكّدة حيًّا في متصفح على عرض 337px (مقاس شاشة موبايل حقيقي)، مش تقديرات:

- **الهيدر مضغوط**: 155px → **114px**. الشريط العلوي الداكن (الجملة + «تتبع الطلب» + «لوحة التحكم») بيختفي تحت 640px، فـ«لوحة التحكم» بقات بندًا في جولة القائمة نفسها عشان ما تضيعش («تتبع الطلب» كان أصلًا فيها، و«تواصل» لسه في الفوتر). اللوغو 40×19، والعنوان 1rem، وخانة البحث 44px.
- **ارتفاع الهيدر مقسوس لا متخيَّل**: `src/hooks/useStickyHeaderOffset.js` بيقيس `.site-header` بـ ResizeObserver ويكتبه في `--header-h`، فأي عنصر لاصق تحته (شريط أدوات الكتالوج) بيرجع مظبوط سواء القائمة المفتوحة (487px) أو المقفولة (114px). قيمة 112px في `tokens.css` احتياط لأول ثانية بس.
- **شبكة بعمودين زي المتاجر**: تحت 640px `grid--products` و`grid--categories` بعمودين، وتحت 420px الأقسام عمود واحد. عرض البطاقة بقى 152px، فتفاصيلها الداخلية تتقلّص بـ **container queries** (`@container product-card` / `category-tile`) على مقاس البطاقة لا مقاس الشاشة: اسم بسطين، وزر «أضف للسلة» بعرض البطاقة، والوصف ورمز الصنف وسطر الجملة يلفّوا على سطور.
- **الفلاتر ورا زرار**: العمود الجانبي (كان 1330px طول نازل تحت القائمة) بقى طبقة تُفتح من زرار «الفلاتر» في شريط لاصق علوي، والزرار بيعرض عدد الفلاتر الشغّالة، واختيار قسم أو وسم أو «إزالة الفلاتر» بيقفل اللوحة. الترتيب اتنقل للشريط العلوي نفسه بدل ما يتكرّر في اللوحة.
- **أهداف اللمس**: 44px للأزرار وأزرار الكمية وخيارات الفلاتر وروابط القائمة؛ 40px للزرّات الصغيرة داخل البطاقة وchip الفلاتر؛ 36px لروابط الفوتر ونقاط مسار التنقل (كانت 23px وخمس نقاط متلاصقة) وزرار «حذف» سطر السلة (كان 31px). و`:active` بيعطي رَدّ فعل فوري بدل الـ hover اللي الموبايل ما بيعرفوش.
- **الحقول 16px**: تحت 640px كل `.field` و`.header-search__input` خطها 16px — أقل من كده iOS بيعمل تكبير تلقائي للمدخل، وده مش اختيار العميل. وخانة رقم التواصل في `/checkout` بقت `type=tel` مع `inputmode=numeric` (لوحة أرقام مباشرة) و`autocomplete=tel`، والاسم والعنوان ليهم `autocomplete` المناسب.

- **البحث في الهيدر بيقترح وانت بتكتب**: الهيدر **كان أصلًا لاصقًا** (`position: sticky` على `.site-header`) وخانة البحث جواه (`order: 3; flex-basis: 100%` تحت 900px)، فاللي ناقص ما كانش شريطًا ثابتًا لكن **الإكمال التلقائي**. الحقل اتلفّ في `.header-search-wrap` (`position: relative`) وتحته طبقة `.header-search__suggests` (z-index 31 فوق الهيدر 30 وتحت شريط السلة 35) فيها خمس أصناف + سطر «كل نتائج «…»». القياس بالـ DOM على عرض 352px: الطبقة عرضها **313px** بالظبط عرض الصندوق اللي فوقها، وأربعة صفوف كلها **44px** (هدف الإصبع)، وما كانش تمرير أفقي (`scrollWidth` = `clientWidth` = 337). أسهم ↑/↓ تتنقل بين الاقتراحات وEscape تقفلها وEnter تودّي للصنف المختار مباشرة (اتأكدنا: `ولاع` ← سهم تحت ← Enter = `/products/long-neck-lighter`)، و`aria-autocomplete=list` + `aria-expanded` مربوطين بالنتايج. وحرف `/` من أي مكان في الصفحة بينقّل للفورم — بيتم تجاهل لو العميل بيكتب في حقل أو عند ضغط Ctrl/Alt/Meta، ولما الحول يخلص `/` تتكتب عادية. الاقتراحات من `src/utils/searchSuggest.js` بنفس حقول ومطابقة صفحة المنتجات (تطبيع + «ال» + جمع + وحدة البيع)، فالبحث في الاتنين بيجاوب بنفس الكلام. **العرض على الشاشات العريضة مقاس متخيَّل لا مقيس**: الغلاف ليه سقف `520px` زي الخانة نفسها — ومعاها الطبقة تبقى بعرض البحث لا أطول منه — بس المتصفح المدمج عندنا 352px، فمراجعة شكلها على شاشتك لسه مطلوبة.

## شعار الشركة وشاشة الترحيب

- **الشعار الحقيقي المقتطع من صورة التاجر** (ملفات PNG محلية، بلا أي خدمة خارجية):
  - `src/assets/brand-emblem.png` (238×108) — الشعار المجنّح مع اللهب، بلا نص. يستخدمه الهيدر (`Header.jsx` → `.brand__mark` بـ 64×30) حتى يبقى الشريط العلوي مضغوطًا.
  - `src/assets/brand-logo.png` (307×222) — العلامة كاملة مع نص «DELTA TRADE». تستخدمها شاشة الترحيب وحدها.
  - `public/favicon.png` (238×238) — نفس الـ emblem مؤطّرًا على مربّع لأيقونة المتصفح؛ `index.html` يشير إليه بدل الـ SVG.

- **شاشة الترحيب** (`src/components/layout/Splash.jsx`، أعلى `<Routes>` في `App.jsx`): تُعرض **مرة واحدة عند فتح الموقع** ولا تتكرر عند التنقل الداخلي؛ اللوجو على بلاطة فاتحة + جملة «كل اللي بيتك ومحلك محتاجه، في مكان واحد» + الاسم القانوني وعنوان المخزن من `company.js` (لا هاتف ولا بريد لأنهما غير معتمدين). المدة 3 ثوانٍ (`SHOW_MS`) ثم تلاشٍ 420ms (`FADE_MS`).
  - **شكلها الافتتاحي**: اللوجو على بلاطة بيضاء بحلقة ذهبية 1px، ثم حلقة زرقاء غامقة 8px، ثم حلقة ذهبية أخفت — تُقرأ كميدالية لا كصورة ملصقة، وفوقها لمعة ذهبية تمرّ مرة واحدة (`splash-sheen`). الجملة بحجم عرض `clamp(1.35rem, 4.6vw, 2.2rem)` ووزن 800 مع تذهيب «في مكان واحد» (`--gold-300`)، وبعدها فاصل ذهبي رفيع في منتصه معيّن (`splash__ornament`)، ثم سطر الشركة بحروف متباعدة 0.3px. إطار ذهبي مزدوج رفيع داخل حافة الشاشة (`::before` و`::after`) — بلا تدرّجات مصطنعة ولا زخرفة.
  - **حقل أزرق غامق لا كحليّ الموقع**: خلفية الشاشة من `--deep-blue-950/-900/-800` (بإضاءتين شعاعيتين فقط) وهي **خاصة بالافتتاح**؛ أما `--navy-*` فتظل لون الهوية في الهيدر والصفحات. قرار المالك: الخلفية أزرق غامق أعمق، والذهبي يبقى كما هو.
  - **لمسات الذهب محصورة**: `--gold-500/-400/-300` في `tokens.css` تُستعمل على الأزرق الغامق فقط (شاشة الترحيب)، ولا تنزل على نصوص الصفحات الطويلة.
  - **البلاطة بلا `overflow: hidden`**: اللمعة تُرسَم بتحريك `background-position` داخل صندوق الـ pseudo نفسه (`background-size: 260%`)، لأن `overflow: hidden` على البلاطة يصفّر حدها الأدنى كعنصر grid فتُضغط ويُقصّ اللوجو — وهو خطأ فعلي ظهر في نافذة 450×425 واتثبت بالقياس (`scrollHeight` 226 مقابل صندوق 158). للنافذة القصيرة كمان `@media (max-height: 620px)` يصغّر البلاطة والجملة حتى لا يتجاوزا الإطار.
  - **الظهور متدرّج**: البلاطة تنزل وتستقرّ (`splash-settle` 720ms)، فالجملة تصعد (300ms تأخير)، ثم الفاصل يتمدّد من منتصه (`splash-wipe`، 520ms)، فسطر الشركة (700ms)، والإطاران بعد ذلك — كله ينتهي قبل ~1.3 ثانية من أصل 3.
  - تُتخطّى بالكامل عند `prefers-reduced-motion: reduce` (`useState(!prefersCalmMotion())` — بلا `setState` داخل مفعول)، وتُخفى عند الطباعة (`print.css`)، وطبقتها `z-index: 120` فوق السلة والإشعارات، وحركتها تُبطَل مع تقليل الحركة بحارس `motion.css` العام.
  - وقتها محكوم في `src/components/layout/Splash.test.jsx` (2999ms/3000ms/3420ms). شكلها أُكّد **بلقطة شاشة فعلية** في المتصفح المدمج (بإيقاف `SHOW_MS` مؤقتًا لأن الالتقاط أبطأ من 3 ثوانٍ، ثم أُرجع إلى 3000 وأُعيد تشغيل الاختبارات)، وبقياس الأنماط المحسوبة أطوالَ البلاطة والجملة والحلقات والإطار. لقطة المراجعة الثانية للأزرق الغامق منعها اختفاء سطح المتصفح (`visibilityState: hidden`)، فالتأكيد الأخير كان قياسًا لا صورة: بلاطة 260×190 بارتفاع محتوى 190 ونسبة صورة سليمة داخل حدودها. العرض المتاح كان 450×425، فمراجعة شكلها على شاشتك الكاملة لسه مطلوبة.

## الحركة (src/styles/motion.css)

- ظهور متدرّج `rise-in` لبطاقات المنتجات والأقسام وأسطر السلة ونتائج التتبع وبطاقات مؤشرات اللوحة؛ ترتيب العنصر يُمرَّر من JSX في متغيّر `--i`، والتأخير `calc(var(--i) * 45ms)` بحد أقصى 420ms حتى لا يطول الانتظار في القوائم الطويلة.
- تفاعل: البطاقة ترتفع 3px مع ظل عند المرور، وصورة المنتج تقترب قليلًا، والأزرار والشيبس تنضغط `scale(.97)` عند الضغط.
- مسار التتبع: المراحل تظهر بالترتيب، وخط المسار ينمو رأسيًا عند المرحلة Reached، ونقطة المرحلة الجارية تنبض مرة واحدة.
- الطلبات: صف اللوحة يومض `row-flash` بعد تغيير حالته (مفتاح الصف في `Dashboard.jsx` يشمل الحالة فيعيد تركيب الصف فتُشغّل الحركة من جديد)، وقيمة السعر تعمل لها `pop-in` عند تحوّل الأساس بين قطاعي وجملة وعرض.
- كل هذا يُبطَل تلقائيًا عند `prefers-reduced-motion: reduce` (تصير المدة 0.01ms وتُلغى الإزاحة والتكبير)، فلا إزعاج لمن يفضّل تقليل الحركة.

## البحث العربي

- `src/utils/arabic.js` يطبّع النص قبل المطارنة: الهمزات (أ/إ/آ/ٱ → ا)، ؤ → و، ئ → ي، ى → ي، ة → ه، إزالة التشكيل والتطويل، وتحويل الأرقام العربية إلى لاتينية.
- كلمات البحث تُطابَع كلها (AND) على نص واحد مبنِي من: الاسم + الوصف + رقم الصنف + الـ slug + وحدة البيع + اسم القسم.
- تُجرَّب صيغ إضافية لكل كلمة: مع/بدون «ال» التعريف، ومفرد تقريبي عند نواحي الجمع (ات/ين/ون/ان)، فيصير «ولاعه» و«الولّاعات» و«ولاعات» نتيجة واحدة.
- نفس التطبيع يُستخدم في بحث لوحة التحكم، فلا يحتاج التاجر إلى كتابة الرقم بحالة معينة. بحث اللوحة يضيف مكان الرف إلى نص المطارنة («رف B3» يوصل للصنف)، بينما بحث المتجر عند العميل لا يعرف هذا الحقل إطلاقًا.
- **اقتراحات الهيدر من نفس المِشعَر**: `src/utils/searchSuggest.js` بيبني النص المطبَّع من الحقول نفسها اللي بتستخدمها صفحة المنتجات (الاسم + الوصف + رقم الصنف + الـ slug + **وحدة البيع + عدد القطع** + سلسلة الأقسام) وبيطابق بكل كلمات البحث بنفس `matchesAllTokens`، فاللي يكتب «ولاعه» في الهيدر بياخد نفس الكروت اللي تاخدها في `/products?q=ولاعه` — مش مصدرين بيجاوبوا مختلف. الفرق الوحيد: الاقتراحات بحدّ خمس أصناف وبمقدمة التطابق الأول بالحرف، وصفحة المنتجات بتدي كل النتائج بكل الترتيبات. **ووحدة البيع كانت فرقًا فعليًا**: القياس الحي الأول طلع «علبة» = ٤ كروت في البحث الكامل و٣ اقتراحات بس، لأن الحقول ما كانش فيها `unit` و`countUnit` — اتضافوا، وبعدها القياس بقى ٤↔٤ و«ربطة» ١↔١، والاتنين بالـ DOM على منفذ التطوير.

## الأداء والتثبيت (بلا Backend وفي حدود المتصفح)

- **اللوحة لوحدها في حزمة**: `/dashboard` اتحوّلت لـ `React.lazy` + `Suspense` في `src/App.jsx`، ولوحاتها الست بتيجوا معاها في نفس الحزمة (رسالة الانتظار `<p className='route-fallback'>لوحة التحكم بتحمّل…</p>` بارتفاع ثابت يمنع القفزة). قبل التعديل كانت حزمة واحدة **521.63 kB / gzip 147.87**؛ بعد البناء: `index-*.js` **451.92 kB / gzip 132.65** + `Dashboard-*.js` **76.70 kB / gzip 19.52** — يعني العميل على الموبايل ما بينزّلش **76.7 kB** (‏19.5 kB مضغوطة) اللي هو أصلًا ما يفتحهاش. التنقل للوحة تأكد منه حيًا: الضغط على تبويب «المنتجات» في الشريط الجانبي بلّغ `?tab=products` وجدّع **٥٢ صنفًا** في الجدول وبلا تمرير أفقي، فالشحنة المتأخرة بتشتغل بعد ما توصل.
- **`public/manifest.webmanifest`** مربوط في `index.html` مع `apple-touch-icon`: الاسم «الدلتا»، `lang: ar`، `dir: rtl`، `display: standalone`، `theme_color: #0b2440` (الكحلي بتاع الهوية)، `background_color: #f5f7fa`، وأيقونتان بمقاسيهما الحقيقيين `favicon.svg` (`any`) و`favicon.png` (`238x238`) — ما حطيناش مقاسات متخيَّرة. المانيفست **بلا service worker**: يعني يقدر يتثبّت على الشاشة، بس ما يشتغلش أوفلاين — ده حدّ مقصود لأن التخزين المؤقت Offline ما كانش مطلوب في المرحلة دي. `npm run build` بيخرجه في `dist/manifest.webmanifest` وخادم التطوير بيرد 200 على `/manifest.webmanifest` (متأكد بالاتنين).
- **«شوفت من قبل» في متصفح العميل**: `src/utils/recentlyViewed.js` بيخزّن آخر **٨** معرّفات أصناف في `delta-store:recently-viewed` (الأحدث أولًا، بلا تكرار — الصنف نفسه ما بيتسجلش مرتين)، و`Home.jsx` بيعرض أول **٤** منها في شريط فوق «الأقسام» بمسمّى «شوفت من قبل» وتحتها سطر صريح إنها بتسجّل محليًا وبلا حساب وبلا بيانات شخصية. الصنف اللي يتشال من اللوحة بعد كده بيُسقَط من الشريط بدل كارت مكسور. التسجيل بيتم في صفحة الصنف وحدها (`ProductDetail.jsx`) ولا تحصل في أي مكان تاني، فالشريط ما بيتلخبطش من تصفّح الأقسام والفلترة: **اتأكد حيًا** — بعد ثلاث صفحات بقوا تلاتة في الشريط وبنفس الترتيب، وبعد مسح المفتاح القسم اختفى من DOM خالص.
- **روابط التواصل بتتبني من الرقم كما يُملى**: `src/utils/contactLinks.js` بيشيل أي رمز من غير الأرقام في `tel:` (وتُبقي «+» في الأول عشان الرقم الدولي يفضل شغال) وبيشيل «+» والمسافات في `wa.me` (اللي بيرفض أي غير أرقام). **مفيش رقم مخترَع**: مع `phone: null` و`whatsapp: null` — وهي الحالة الحالية — مفيش أي `tel:` ولا `wa.me` في الصفحة خالص، والسطر ده ماشي على صفحة الصنف وصفحة التواصل. والتحقق إن الزرار هيظهر لما الرقم يعتمد اتعمل بملف مؤقت: نسخ `company.js` واحتياطه، ثم تعبئته بـ `0109 123 4567` و`+20 109 123 4567` (بيانات اختبار لا تُترك في المشروع)، فظهر `tel:01091234567` و`https://wa.me/201091234567?text=…` في صفحة الصنف و `/contact` — و**بعدها رجع الملف بايت-بايت كما كان** (تأكيد بـ `cmp` و`md5sum` على النسختين) وأُعيد القياس الحي فمابقش ولا رابط اتصال ولا الرقم التجريبي موجود في الصفحة.

## الفاتورة والتصدير وإعادة الطلب (كلها محلية)

- `/invoice/:number` يعرض فاتورة الطلب، وزر «طباعة أو حفظ PDF» يستدعي طباعة المتصفح مباشرة. قواعد `src/styles/print.css` تُخفي الهيدر والفوتر والسلة والإشعارات عند الطباعة وتضبط الورق على A4.
- الفاتورة تُظهر الأصناف بأسعارها المحفوظة لحظة الطلب، ثم ثلاثة أسطر في أسفل الجدول: إجمالي الأصناف، بند التوصيل (مسمّى ومقابلة، أو «توصيل مجاني / بلا مقابل» عند تجاوز الحد)، والمبلغ المطلوب — وكلها من اللقطة المخزّنة مع الطلب لا من القواعد الحالية. وتنصّ بوضوح أنها تجريبية: لا رقم ضريبي ولا فاتورة إلكترونية ولم تصل إلى الشركة. تُطبع بيانات الدلتا المعتمدة (الاسم وعنوان المخزن في مركز الزرقا — دمياط)، أما الهاتف فلا يظهر لأنه لم يُعتمد بعد.
- تصدير CSV من تبويب الطلبات في اللوحة يصدّر الطلبات المفلترة والمعروضة فقط، بترميز UTF-8 مع BOM ليقرأ Excel العربية صح، وينزل الملف من المتصفح بدون أي خادم.
- **تصدير الجرد** من تبويب المنتجات (`src/utils/inventoryExport.js`) يبني نفس الفكرة للأصناف: ١٦ عمودًا (الرمز، الصنف، القسم، **مكان الصنف**، وحدة البيع، محتوى الوحدة، قطاعي/عرض/جملة، حد الجملة، الحد بالقطعة، المخزون، **العدد الفعلي**، **فارق الجرد**، حالة المخزون، جاهز للجملة) للصف المعروض بعد فلاتر البحث والقسم و«بلا سعر جملة» و«فروق جرد»، والأرقام تخرج بلا فواصل آلاف لتقرأها Excel كأرقام. الخانتان الأخيرتان تُملآن من سجل العدّ، والصنف الذي لم يُعدّ يبقى فارغًا. الزر يتعطّل لما لا تكون هناك صفوف، والرسالة تؤكد أن الملف يبقى على الجهاز.
- **ورقة التجهيز** `/pick/:number`: أصناف الطلب وكمياته ومحتوى العبوة والمجموع بالقطعة **بدون أي أسعار**، مع مربّع «تم» لكل صنف (تحديد محلي في الذاكرة فقط، مع عدّاد «جهّزت X من N» وزر تحديد الكل) وخانة «المكان» التي تُطبع من المكتوب في اللوحة وتبقى مخطّطة (`pick-blank`) لما لم يُحدَّد بعد. `print.css` تخصص لها قواعد طباعة (تخفيف الألوان، حدود العمود الفارغ، ومنع تقسيم الصف). طلب غير موجود يعرض حالة خالية برابط للوحة وللتتبع.
- «إعادة الطلب» في التأكيد والتتبع والفاتورة واللوحة تُضيف أصناف الطلب إلى السلة بنفس منطق صنف واحد لكل منتج، وتتجاهل ما لم يعد موجودًا أو نفد مخزونه مع إشعار يوضّح العدد.

## التسعير والسلة

- منطق التسعير كله في `src/utils/pricing.js`: عند بلوغ `wholesaleMinQuantity` يُطبَّق سعر الجملة، وإلا السعر القطاعي (أو سعر العرض إن وُجد). لا يُكرَّر هذا الحساب في أي مكوّن.
- الفراغ معناها غياب لا صفر: `offerPrice` أو `wholesalePrice` بـ `null` أو `''` لا يفتحان عرضًا ولا جملة، فلا يظهر سعر 0 ج.م على البطاقة أو الفاتورة.
- السلة في `src/context/CartContext.jsx`: صنف واحد لكل منتج (الإضافة تزيد الكمية)، والإجماليات مشتقّة من `buildCartLines` + `summarizeLines`.
- تُحفظ السلة في `localStorage` بمفتاح `delta-store:cart` وتُستعاد عند التحديث.
- الكميات تُقيَّد بالحد الأدنى (1) وحد المخزون المتاح، والمدخلات غير الرقمية تُتجاهل.
- الطلب بالعبوة: `packSize` + `countUnit` يحددان محتوى الوحدة (علبة = 20 عود). `quantityOptions` يبني أزرارًا جاهزة في صفحة الصنف (عبوة واحدة، حد الجملة، ضعف الحد — في حدود المخزون فقط)، و`innerCount` يحوّل الكمية إلى المجموع بالقطعة. في السلة يصبح تنبيه «ناقصك لسعر الجملة» زرًا واحدًا يقفز للكمية الكاملة، ويتحول إلى نص فقط إذا كان حد الجملة أكثر من المتوفر.

## حدود هذه المرحلة

- كل الأسعار والكميات وحالات الطلبات **تجريبية** وليست أسعار الشركة المعتمدة.
- لا يوجد Backend أو قاعدة بيانات: تسجيل الطلب والفاتورة وورقة التجهيز وتصدير CSV وملف الجرد يعملون داخل متصفحك فقط (localStorage + تنزيل ملف) ولا يصلون إلى أي جهة. لذلك لا تُدخل بيانات عملاء حقيقية، ولوحة التحكم تعرض تنبيهًا يشرح ذلك وتوفّر مسحًا محليًا بتأكيد من خطوتين.
- الفاتورة ليست ضريبية: لا رقم تسجيل ضريبي، ولا ختم معتمد، ولا بيانات تواصل — تُطبع من المتصفح للعرض والتنسيق فقط.
- **النشر مسموح به ابتداءً من 2026-11-01 بقرار التاجر نفسه**: مستودع عام على GitHub تحت حسابه (`mohamedtharwat556/delta-store23`) مربوط بـVercel على خطة Hobby المجانية، فالجملة القديمة «لا تنشر المشروع على الإنترنت ولا تنشئ حسابات أو خدمات مدفوعة» رفعت لهذا الحد. اللي فضل ساريًا وما يتغيرش بالنشر: لا Backend ولا قاعدة بيانات، ولا إرسال أي بيانات لجهة خارجية، ولا خدمات مدفوعة (Vercel Hobby المجاني هو السقف — ترقية Pro أو أي إضافة مدفوعة قرار جديد منه)، ولا أسرار أو مفاتيح في الكود، ولا بيانات عملاء حقيقية في أي مكان. وبعملية النشر دي بقى لازم ينتبه ل حاجتين ما كانتوش مطروحات والمتجر محلي: الروابط المنشورة يقراها أي حد في العالم، ولوحة `/dashboard` بلا خادم يقف وراها (انظر بند البوابة أدناه).
- الصور كلها ملفات محلية داخل المشروع (SVG للأصناف، وPNG للشعار وPNG لأقسام التاجر) — لا روابط خارجية ولا صور من الإنترنت، وده فضل صحيح بعد النشر لأن الحزمة تُبنى من الملفات الملتزَمة في المستودع.
- **أصل ملفات الشعار**: القصّ تم محليًا من صورة التاجر الملتقطة بالموبايل فوق واجهة عرض وهمية — كان فيها ميل نحو 9° فاعتدل، ثم فُصلت الخلفية بالترشيح اللوني، وأُلغيت النقط المتفرقة حول العلامة بفلترة المكوّنات المتصلة، وأُطّر الشعار على مربع. النتيجة صالحة للعرض على الشاشة لكنها ليست متجهية: حدّتها تظهر عند التكبير الكبير، والأصل الأنقى للمطبعة واللافتة يبقى ملف الشعار المتجه أو الصورة الأصلية غير المضغوطة من صاحب الشعار. لم تُستخدم أي خدمة خارجية ولم تُرسل الصورة لأي مكان.
- الهاتف والبريد ومواعيد العمل والرقم الضريبي غير معتمدة من الشركة بعد، فلا تظهر في الواجهة. الوحيد معتمد هو موقع المخزن: مركز الزرقا — محافظة دمياط. وزرارا «كلّمنا عن…» و«اسأل على واتساب» في صفحة الصنف مربوطين بنفس الاعتماد: يظهرون لحظة تعبئة `contact.phone` أو `contact.whatsapp` في `src/data/company.js`، والآن لا يظهر واحد منهما (مؤكد بالـ DOM: صفر روابط `tel:` و`wa.me` في الموقع كله).

الإعلان اتشالت من العرض» فوق) و**اتأكدنا إنهم وقعوا للصنف الممثل**: رسم SVG محلي بحالة `complete=true` و`naturalWidth=400` في **نفس** صندوق 287×216، يعني **مفيش فراغ ولا صورة مكسورة** في البطاقتين. **الشارات ما اتبدلتش**: البخور «4 قسم»، الولاعات «3 صنف»، مواد سريعة الاشتعال «3 قسم»، أعياد ومناسبات «1 قسم»، عناية الاسنان «2 قسم»، عناية منزلية «5 قسم»، حجائر «0 صنف». وفي شريط الفلاتر الصفوف الـ١٦ بترتيب الإملاء و«حجائر» سادسها بـ`title` «0 صنف»، وصفحة الأصناف لسه ٥٢ كرتًا. **الأقسام الفرعية بلا صورة** — ما بنختلقش واحدة. **نقطتان على الشكل لازم تعرفهم**: (1) **ده كان قبل الشريط الدائري** — من 2026-10-31 صورة البطاقة **دائرة** (`ratio='square'` + `border-radius: 50%`) قياسها الحيّ **132×132px على عرض 352px**، فبدل القصّ من الأطراف بتخسر الصورة **أركانها** مع الدائرة، والعرض الأعرض من 1:1 يخسر **جوانبه** أولًا في المربّع (راجع فقرة «صور الأقسام» فوق). و(2) ثلاث صور مصدرها صغير — عناية منزلية 538×360 وأدوات مكتبية 640×360 وعناية الاسنان 715×429 — فلو اتعرضت على بطاقة أعرض من كده هتبقى **ناعمة/مبهمة**، والأحسن يتبدلوا بأعلى دقة عنده. والصور مش فورية: `loading='lazy'` فاللي تحت مسافة التمرير يفضل `is-pending` (رمادي) لحد ما يبان، و«عناية منزلية» اتأكدنا إنها بتحول `is-loaded` أول ما تنزل للعرض. **على القرص مقابل الحزمة**: `src/assets/categories` فيه **16 ملفًا (≈2.8 ميجابايت)** زي ما ملّاه التاجر — والملفان اللي بطلنا نستوردهم **ما اتشالوش**، ومعاهم `originals/` بنسخ الأربع اللي اتعاملنا معاهم (≈1 ميجابايت) — بس `npm run build` بيشحن **14** JPG بس: اللي ليهم استيراد في `categories.js`؛ اتأكدنا من قائمة `dist/assets` إن `incense` و`flammables` طلعوا منها (≈343 كيلوبايت أقل) وإن `originals/` ما دخلش خالص.
- **الشريط الدائري والممرّ متأكّدين حيًّا بالـ DOM (352px)**: `/products` بلا اختيار = **17 دائرة** حلقتها 68px وصورتها 64px (`1 / 1` + `object-fit: cover` + `border-radius: 50%` على غلاف `overflow: hidden`)، و`?category=incense` = «أقسام البخور» بحلقات 54px وأربع دوائر + «كل البخور»، و**`?category=incense-insam-pyramid-cone`** = «أقسام هرمي» بشريط إخوة («كل هرمي 3 قسم» + مخروطي/وسط/غالي بـ«1 صنف»/«5 صنف»/«3 صنف») وممرّ من خمس عقد «كل الأقسام › البخور › بخور إنسام › هرمي › مخروطي» و**كرت واحد**. **والفلتر صارم على القسم نفسه** (بعد أمر التاجر في نفس اليوم): البخور **٠ كرت** + حالة «قسم بأقسامه» بروابط أبنائه الأربعة، «بخور تيجاني» **١**، «أعواد تيجاني» **٤**، «عناية منزلية» **٥** (أب عليه أصناف بنفسه فأبناؤه ما يسقطونش صنافه)، «الكبريت» **٣**، و«البالون» (ورقة فاضية بلا أبناء) يرجع للرسالة العامة «لا نتائج مطابقة». **بضغط حقيقي لا بالـ DOM فقط**: ضغطة على دائرة «بخور تيجاني» ← `?category=incense-tijani` وكرت واحد، وضغطة على رابط «الكبريت» من حالة الإرشاد ← `?category=matches` و٣ كروت، و`?category=matches&min=10` كرتان (الفلتر الصارم وحدّ السعر بيشتغلوا مع بعض). **الفلاتر ما بتسقطش**: `?q=ولاع&min=20&sort=price-asc` + ضغطة على الولاعات → `…&category=lighters` و3 أصناف وخانة البحث لسه «ولاع». **التوسيط في RTL مقاس لا مفترض**: `ringCx === countCx` في ثلاث دوائر و`circleCx 168 === iconCx 168` على بطاقة القسم (`offBy: 0`)، والفاصل شارة↔اسم **4px**. **وبلا تمرير أفقي للصفحة في أي مستوى**: `documentElement.scrollWidth === clientWidth === 337` بينما شريط الرئيسية `scrollWidth 1628` داخل `clientWidth 313` (تمرير جوه الشريط وحده)، و`/categories` = «اختر قسمك» بـ**16 دائرة** (بلا «كل الأقسام») و16 بطاقة دائرية 132px. **اللي ما اتقاستش**: شكل الشريط عند 901px+ (`flex-wrap: wrap` — المتصفح المدمج 352px، فالقاعدة مؤكدة من نصها في ورقة الأنماط لا من رسم)، والتصوير نفسه مرفوض (`visibilityState: hidden`) فتبقى مراجعة العين على شاشتك مطلوبة.
- الاختبارات تغطي منطق التسعير والسلة والطلبات والبحث والتصدير داخل jsdom؛ ما لا تغطيه هو نافذة الطباعة نفسها عند الحفظ PDF، وتُراجع يدويًا في المتصفح. وبالأخص قاعدة `container-type: normal` اللي بتشيل حالة البطاقة من الورق في `print.css` — تأكيدها كان من نص القاعدة في ورقة الأنماط، لأن المتصفح المدمج مفيهوش محاكاة وسائط الطباعة، فمعاينة «طباعة» الحقيقية على فاتورة وورقة تجهيز لسه مطلوبة.
- عدّاد الكمية في السلة وصفحة الصنف يفلتر الأرقام غير اللاتينية أثناء الكتابة، فكتابة الكمية بالأرقام العربية («٦٠») تُمحى من الخانة — الأزرار أو الكتابة اللاتينية تعمل، والتصحيح متاح لاحقًا إن احتاجه التاجر.
- **عدّاد «اللي جوه على طول» بيوصّف المشجر لا الكمية**: «البخور 4 قسم» مع إن تحته ٣٩ صنفًا، و«عناية منزلية 5 قسم» مع إن أصنافها الخمسة مسكّنة **على الأب نفسه** وأقسامها الخمسة فاضية (نفس الشكل في الفحم: صنف على الأب وتحته قسمين). الرقم بقى مش دليلاً على عدد اللي هتلاقيه لما تضغط، فاللي عايز يشوف الأصناف ياخد مدى الأسعار على البطاقة أو عدد الكروت بعد الضغط. **وبعد الفلتر الصارم (2026-10-31) بقى الانقطاع أوضح**: دائرة «البخور» تكتب «4 قسم» والكرتات تحتها **صفر** + إرشاد لأبنائها، لأن العدّاد يوصّف الشجرة والفلتر يقرأ القسم نفسه فقط. **لو التاجر أحبّ يظّب ده**: يتنقل الأصناف من الأب لأقسامها (عناية منزلية → مشبك غسيل/نفتالين/…، و`DL-1105` «الجو تيجاني» → قسم ورقي) فالمشهد يبقى متسقًا؛ ده قرار تسكين أصناف مش قرار واجهة.
- **خريطة الأقسام في فترة بناء**: **١٢ من الأقسام الرئيسية الـ١٦ بلا أصناف بعد في شجرتها كلها** (ملمعات الأحذية، ماكينات الحلاقة، اللواصق، حجائر، ميدالية ومحفظة، **أعياد ومناسبات**، خلة وسلاكة، أكياس شامبو وجل، عناية الاسنان، **أدوات مكتبية**، **ألعاب أطفال**، **أدوات كهربائية**) — بطاقاتها تقول «لا أصناف في هذا القسم بعد» ولا نخترع لها أصنافًا أو أسعارًا. منهم **عشرة بلا أقسام فرعية** فعدّادها يفضل «0 صنف»، واثنان جوه أقسام فيعدياهم `sectionCount`: «عناية الاسنان» (سيجنال، كلوزاب) تظهر **«2 قسم»**، و**«أعياد ومناسبات» الجديدة تظهر «1 قسم» لأن ابنها الوحيد هو «البالون» المنزّل** — الفراغ اللي بيتقال للعميل هو فراغ أصناف لا فراغ قسم. ومجموع الأوراق البلا أصناف **٢٠ قسمًا**: العشرة الرئيسية دي + عشر أوراق تحت الرئيسية («الغاز» و«أقراص سريعة الاشتعال» تحت مواد سريعة الاشتعال، والبالون تحت أعياد ومناسبات، وسيجنال وكلوزاب، ومشبك غسيل ونفتالين ولزقة فار واستك ملابس واستك فلوس). أسماء منسوخة كما أملاها التاجر، و«حجائر» و«خلة وسلاكة» و«استك ملابس/استك فلوس» و**الثلاثة الجديدة (أدوات مكتبية، ألعاب أطفال، أدوات كهربائية)** تحتاج توضيح منه قبل صياغة وصفها للعميل — فوصفها المؤقت «أصناف هذا القسم تُحدَّد من التاجر.»، ووصف «مواد سريعة الاشتعال» رتبناه من أوصاف أبنائه اللي أملاها وهو لسه مستني تصحيحه أو إملاءه.
- **بخور إنسام مسعَّر ناقص الباقي**: الأصناف الاثنان والعشرون (`DL-1201`…`DL-1239` مع فراغ `DL-1208`…`DL-1224` بعد دمج مخروطي) دخلت بسعرها القطاعي كما أملاه التاجر، فهي قابلة للشراء وتدخل فلاتر السعر والترتيب على خلاف أصناف تيجاني. لكن `unit` و`packSize` و`countUnit` و`stock` و`location` ما زالت `null` (تعرض «—» و«المخزون غير محدَّد» بلا اختلاق)، و`wholesalePrice`/`wholesaleMinQuantity` `null` فتعرض «قطاعي فقط» — **لو إنسام صنف جملة عنده** فحدّ الجملة ومثلها ناقصين لكل صنف. الصور: الأعواد لبست `bakhoorSticksBox` ودرجات الهرمي الثلاث لبست `bakhoorConesBox` (نفس قرار تيجاني)، أما بودر الأكياس والاستاند والمكعبات وأريلاكس فبلا صورة وتعرض «بلا صورة بعد».
- **أسماء إنسام منسوخة من إملائه والتاجر اعتمد التصحيحات**: كتبنّا «إنسام» بالهمزة و«الأقصى» و«الأندلس» و«أربيسك» و«أريلاكس» و«مكعبات أصالة» و«مملكة الورد» (أملاها «انسام/الاقصي/الاندلس/اربيسك/اريلاكس/اصالة/ممكلة»)، وعرضنا عليه القراءات التلاتة الباقية اعتمدها كما هي: «اعواد يوجا -مزاج-تامل» صنف واحد اسمه «أعواد إنسام — يوجا / مزاج / تأمل» بـ555 (ولو انقسمت على تلات أعواد يتقاسموا الـ555)، و«أربيسك» صنفين بسعرين (590 في مخروطي و1160 في غالي) — وبعدها لمّا اندمجت «مخروطي» في صنف واحد ما بقاش «أربيسك» إلا في الغالي (1160)، واسمه محفوظ مع أسماء المخروطي اللي فوق، و«اكياس 2 جرام» بـ40 مقابل «20 جرام» بـ345 كما أُملي.
- **بخور شعبي بالاسم والقسم فقط (زي تيجاني)**: `DL-1301` «بخور الشربيني» و`DL-1302` «بخور شعبي» — التاجر أملى اسم القسم والصنفين وما وملّش رقمًا، فكل حقول البيع `null`: بلا سعر ولا عبوة ولا مخزون ولا صورة، ولا تُضاف للسلة ولا تدخل فلاتر السعر. اللي ناقص منه هو نفس اللي ناقص تيجاني: سعر القطاعي (والجملة إن كانت)، وحدة البيع، المخزون، ومكان الرف — يقولها فيُملّونها من اللوحة أو من البذرة.
- **بخور ناموس بالاسم والقسم فقط (زي شعبي وتيجاني)**: `DL-1401` «أعواد لوجينا» و`DL-1402` «أقراص الصفا» و`DL-1403` «سائل جهاز الناموس» و`DL-1404` «جهاز الناموس» — التاجر ملّى القسم وأربع حاجات جواه وما ملّش رقمًا، فكل حقول البيع `null`: بلا سعر ولا عبوة ولا مخزون ولا صورة، ولا تُضاف للسلة ولا تدخل فلاتر السعر. الناقص هو نفس ناقص شعبي: سعر القطاعي (والجملة إن كانت)، وحدة البيع، المخزون، ومكان الرف. **وكمان**: ده أول قسم في البخور بَيَعه مش بخور تدخين (جهاز ناموس وسائل)، فلو أراد التاجر يوصّل العميل صح ممكن يتعمل رئيسي لوحده أو يتعدّل وصف البخور — القرار له مش لنا.
- **بخور تيجاني مبني بالاسم والقسم فقط**: الأصناف الأحد عشر (`DL-1101`…`DL-1111`) معمولة كما أملاها التاجر — الاسم والقسم — وكل حقول البيع (`unit`/`packSize`/`countUnit`/`retailPrice`/`offerPrice`/`wholesalePrice`/`wholesaleMinQuantity`/`stock`/`location`) `null` بقراره «سيب السعر فاضي». يعني كمان: لا تُضاف للسلة، ولا تدخل فلاتر السعر، ولا تظهر في «المتوفر فقط»، وتحتاج منه وحدة البيع والأسعار والمخزون لكل صنف قبل ما تبقى قابلة للشراء. «الأربع حاجات» اللي قالها التاجر في البخور اتبيّنت إنها **أقسام بخور تيجاني الأربعة** (أعواد / هرمي / كرتونة متنوعة / بودر أكياس) — اتعملت كلها. وما بقاش في البخور أي عائلة مختلَقة: العائلات الأربع (تيجاني / إنسام / شعبي / ناموس) كلها أسماء وأملاك إملاها التاجر بنفسه.
- **صور تيجاني**: الأعواد والهرمي لبست رسومات المشروع الموجودة (علبة أعواد / علبة أقماع) لأنها قريبة من شكل العبوة، أما «الجو تيجاني» و«كرتونة تيجاني المتنوعة + مبخرة هدية» و«بودر تيجاني — أكياس» فبلا صورة وتعرض «بلا صورة بعد» — ما حطّيناش رسمة غلط عليهم، ولا سحبنا صورة من الإنترنت.
- **المعطرات سكنت مؤقتًا تحت «عناية منزلية»**: لم تكن «معطرات الجو» ضمن قائمة التاجر، فأُلحقت بعناية منزلية مؤقتًا (DL-6001 رذاذ الجو وDL-6002 معلّق السيارة)، بينما إسفنج المواعين وأكياس القمامة ومعطر الأرضيات في نفس القسم طبيعيًا. لو للتاجر قسم تاني للمعطرات يتقفل من تبويب المنتجات في اللوحة أو من `categories.js`.
